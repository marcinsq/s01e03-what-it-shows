Cause 1: shared parser reads month first

379 reports · 11 tenants · app, email, and form

The shared parser reads every date month-first. Tenants whose locale writes the day before the month therefore get swapped dates. For example, report R-41200 says a 7 April reminder went out on 4 July.

The desk’s five oneDayMove notes remain in this cause group. The KB classifies them by tenant configuration; the one-day symptom is not a separate root cause.

Cause 2: booking-v3 hint conflicts with locale parsing

33 reports · 3 tenants · form only

The booking-v3 form displays MM/DD/YYYY, even for tenants whose locale is day-first. People follow that hint, but the form reads the submitted value according to the tenant locale. This creates a separate defect from the shared parser. The affected tenants are alder.physio (12 reports), copper.studio (11), and pale.harbour (10).

Ticket split

File one ticket for each cause: 379 reports for the shared parser and 33 for the booking-v3 hint. These tickets should not be merged based on similar subjects or intake tags.
